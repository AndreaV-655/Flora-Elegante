1. Objetivo de la implantación

Este documento define el plan de implementación del sistema Flora Elegante: preparación del servidor, instalación de la base de datos, despliegue de los archivos, configuración, migración de datos y usuarios, validación con el negocio (pruebas de aceptación), capacitación, respaldo, plan de rollback, soporte y mantenimiento. El objetivo es llevar el sistema a producción local (XAMPP) y dejar lista la operación diaria de la florería: catálogo, ventas, chatbot, reporte mensual y CRM.

2. Arquitectura destino

La implantación se realiza sobre el mismo stack desarrollado: Apache + PHP 8 + MySQL/MariaDB (XAMPP) en un servidor Windows. No se requieren servicios externos: las librerías (Tailwind, Font Awesome, fuentes) están versionadas en la carpeta vendor/, de modo que el sitio funciona incluso sin conexión a internet.

3. Plan de instalación

3.1 Paso 1 — Verificación de prerrequisitos

  • Verificar que Apache y MySQL están iniciados en el panel de XAMPP (puertos 80 y 3306, sin conflictos).
  • Verificar PHP 8 y extensión PDO MySQL con php -v y una página .
  • Confirmar carpeta htdocs escribible por el usuario del sistema.

3.2 Paso 2 — Instalación de la base de datos

  1. Crear la base flora_elegante con cotejamiento utf8mb4_unicode_ci (phpMyAdmin o consola MySQL).
  2. Importar sql/flora_elegante_mysql.sql: crea las 8 tablas, índices, restricciones y los datos semilla.
  3. Verificar en phpMyAdmin: número de tablas = 8, productos = 6, categorías = 6 e interacciones = 15.

3.3 Paso 3 — Copia de archivos

Copiar la carpeta del proyecto (index.html, login.html, cliente.html, admin.html, css/, js/, api/, sql/, img/, vendor/, diagrams/) a C:\xampp\htdocs\flora-elegante\. Mantener la estructura interna intacta: las rutas relativas y la resolución dinámica de api/index.php dependen de ella.

3.4 Paso 4 — Configuración

  • Revisar api/config.php: ajustar DB_USER/DB_PASS si el destino usa credenciales distintas de root.
  • Revisar direcciones base: el frontend resuelve la API desde document.baseURI, por lo que basta que la URL pública sea http://localhost/flora-elegante/.
  • Revisar el aviso de privacidad con los datos de la florería (responsable, fines, mecanismo de derechos ARCO, contacto).

3.5 Paso 5 — Pruebas de humo en producción local

  1. Abrir http://localhost/flora-elegante/index.html y verificar catálogo, moneda/idioma y chatbot.
  2. Verificar el bootstrap automático: al hacer login primero (o llamar a auth), se crean roles, cuentas demo y pedidos de ejemplo.
  3. Verificación de cuentas demo: admin@floraelegante.mx / Admin2025* (panel completo) y cliente@demo.mx / Cliente123* (perfil, historial, reporte).
  4. Generar un pedido de prueba y verificar descuento de inventario en phpMyAdmin.
  5. Generar una interacción (calificación y sugerencia) y verificar que el reporte del mes la refleja.

Recomendación de higiene: tras la verificación en producción, restablecer/deshabilitar las cuentas demo y limpiar los datos de ejemplo si se desea iniciar operación limpia (ver 4. Migración).

4.2 Verificación post-migración

  • Ejecutar el reporte mensual del mes en curso: debe reflejar la operación real (bloques a, b y c).
  • Comparar el inventario en el sistema contra el conteo físico con el umbral de reposición (≤ 5) visible en el dashboard.
  • Verificar que el CRM no exponga datos sensibles y que el botón de semiprivados funcione.
  • Enviar mensajes de prueba al chatbot con términos comerciales reales de la florería y ajustar Data.botResponses si se detectan vacíos de conocimiento.

7. Plan de respaldo y recuperación

7.1 Respaldo

  • Base de datos: exportación semanal completa de flora_elegante (phpMyAdmin, formato SQL con DROP TABLE + CREATE + INSERT), copiada a un dispositivo externo o servicio seguro.
  • Archivos: copia del proyecto (htdocs\flora-elegante) mensual o tras cada cambio relevante.
  • Rotación: conservar al menos 4 respaldos semanales y 3 mensuales.

7.2 Recuperación y rollback

EscenarioProcedimiento
Corrupción de la BDRestaurar el respaldo más reciente; volver a verificar cuentas y stock.
Actualización fallida del sitioRevertir htdocs a la copia previa (rollback por carpeta); el esquema SQL es compatible hacia atrás.
Pérdida de accesos demoEliminar filas demo y re-ejecutar el bootstrap (crea las cuentas con password_hash).
Desastre completo del equipoInstalar XAMPP, restaurar archivos y BD desde respaldo; repetir pasos 3.2 a 3.5.

9. Cierre de la implementación y entregables

Al finalizar la implementación se entregan: el sistema desplegado y operativo en http://localhost/flora-elegante/, la base de datos migrada y verificada, las cuentas de operación documentadas, el plan de respaldo activo, los formatos UAT firmados y la documentación completa del proyecto en documentacion/. El proceso formal se cierra con la firma de la aceptación, quedando el sistema en estado de producción local con el soporte descrito en la sección 8.
